# Review guide

Guidance for AI and human reviewers of pull requests in this repository. It decides what is worth flagging; it does not change the output format of any review tool.

## What counts as a finding

Flag a change only when it can cause one of these:

- **Data loss or corruption.** Anything that can drop, overwrite, or silently change a user's cars, visits, schedules, receipts, or photos, in browser storage or in Supabase, including during signup transfer and sync.
- **Broken data isolation.** New tables without row level security, policies that let one user read or write another user's rows, `security definer` functions that skip ownership checks, or API routes that act on a record without checking who owns it.
- **Unsafe migrations.** Migrations that drop or rewrite existing data without a backfill, or edits to a migration that has already shipped (changes belong in a new file).
- **Security issues** in `src/app/api` and account code: missing authentication, input not validated with zod, secrets or internal errors returned to the client, missing rate limits on public endpoints such as bug reports, and sign-in, recovery, email change, or deletion flows that can lock users out or act on the wrong account.
- **Wrong reminder behavior.** The daily cron at `/api/reminders` sending duplicate or missed emails, running without authorization, or running unbounded queries.
- **Incorrect calculations.** Rounding, km/mi and currency conversions, due-date and odometer math, and dates compared across time zones.
- **Regressions in existing behavior** described in `README.md` and `docs/`, including accessibility (keyboard access, focus return, accessible labels), unsaved-change guards, and offline use.
- **Missing translations.** A user-facing string added to `messages/en.json` without a matching key in `messages/es.json`, or hard-coded user-facing text in components.
- **Missing tests** for a behavior change in `src/lib`, `src/app/api`, or `supabase/migrations` (SQL tests live in `supabase/tests`).

For bug fixes, check that the change addresses the root cause, and that other instances of the same bug class are fixed too.

## What not to flag

- Formatting and lint issues. Prettier and ESLint run in CI.
- Type errors, failing tests, and build failures. CI runs `pnpm typecheck`, `pnpm test`, and `pnpm build`.
- Naming, style, or refactoring preferences that don't affect behavior.
- Problems that already existed before the PR, unless the PR makes them worse.
- Issues already raised in an earlier review round of the same PR.

## Ignored paths

- `pnpm-lock.yaml`, `next-env.d.ts`
- `.next/`, `coverage/`, `.codegraph/`
- `supabase/seeds/vehicle-catalog.sql` and `supabase/seeds/vehicle-catalog.provenance.json`, generated by `scripts/generate-vehicle-catalog.mjs` (review the script instead)

## Paths that need extra care

These changes always need a human reviewer, even if AI review passes. `.github/CODEOWNERS` enforces this.

- `.github/` (CI and merge gates) and `REVIEW.md`
- `supabase/` (schema, policies, and seeds)
- `src/app/api/` and `vercel.json` (server endpoints and the reminder cron)
- `src/lib/account/` and `src/app/(garage)/auth/` (authentication and account changes)
- `package.json`, `pnpm-lock.yaml`, `pnpm-workspace.yaml` (dependencies)

## Every finding

- Cite the file and line.
- Explain the concrete failure: what input or state leads to what wrong result.
